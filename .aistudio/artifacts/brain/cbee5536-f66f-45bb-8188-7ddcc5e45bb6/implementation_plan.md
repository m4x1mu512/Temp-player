# План оптимизации плавности анимаций на старых устройствах (Android 8+)

## 1. Контекст и архитектурный анализ проблемы

На старых версиях Android (таких как Android 8.0/8.1 Oreo, API 26–27) и устройствах с умеренной производительностью подтормаживания анимаций обычно вызваны следующими факторами в Jetpack Compose:
1. **Рекомпозиция и повторные фазы измерения/компоновки (Measure/Layout pass) на каждом кадре**:
   - В `ExpandablePlayerSheet` при движении шторки размеры (`currentArtSize`) и координаты (`currentArtX`, `currentArtY`) передаются через `Modifier.size()` и `Modifier.offset(x, y)` с прямыми Dp-значениями, заставляя весь граф UI заново пересчитывать разметку каждый кадр (16 мс).
2. **Аллокация объектов в цикле отрисовки (GC Churn)**:
   - В `AudioVisualizerView` на каждом кадре внутри `Canvas` создаются новые экземпляры градиентов `Brush.radialGradient`, `Brush.verticalGradient`, списки цветов `listOf(...)` и объекты геометрии. На Android 8 с более медленным сборщиком мусора это вызывает периодические GC-паузы («микрофризы»).
3. **Тяжелые графические эффекты и аппаратные тени**:
   - Сложные многоцветные тени (`spotColor`, `ambientColor`) с динамической прозрачностью и 3D-вращение с `cameraDistance` на старых версиях OpenGL/Vulkan вызывают задержки рендеринга.
4. **Слишком высокая частота кадров фонового визуализатора**:
   - `AudioVisualizerController` передает новые PCM-сэмплы каждые 20 мс (50 FPS), нагружая CPU параллельно с анимацией интерфейса.

## 2. Архитектура решения и ключевые улучшения

```
┌────────────────────────────────────────────────────────┐
│             DevicePerformanceHelper                    │
│   (Определение Android 8/9, Low-RAM, ядер процессора)  │
└───────────────────────────┬────────────────────────────┘
                            │
            ┌───────────────┴───────────────┐
            ▼                               ▼
┌─────────────────────────┐     ┌─────────────────────────┐
│   ExpandablePlayerSheet │     │   AudioVisualizerView   │
│  - Сдвиг на GPU layer   │     │  - Кэш градиентов/Brush │
│  - graphicsLayer        │     │  - 0 аллокаций в Draw   │
│  - Легкие тени на API<29│     │  - Адаптивный 30 FPS    │
└─────────────────────────┘     └─────────────────────────┘
```

### Шаг 1: Интеллектуальный детектор производительности (`DevicePerformanceHelper`)
- Создание утилиты, автоматически определяющей класс устройства:
  - `Build.VERSION.SDK_INT <= Build.VERSION_CODES.P` (Android 8–9).
  - Проверка `ActivityManager.isLowRamDevice()` и количества доступных вычислительных ядер.
  - Предоставление флага `isLowPowerDevice` / `isSmoothPerformanceMode`.

### Шаг 2: Оптимизация анимации шторки и плеера (`ExpandablePlayerSheet.kt`)
- **Перевод анимации на RenderNode / Draw phase**:
  - Замена тяжелого динамического `Modifier.size(...)` и `Modifier.offset(...)` на фиксированную компоновку с трансформацией через `Modifier.graphicsLayer { scaleX = ...; scaleY = ...; translationX = ...; translationY = ... }`. Разметка измеряется **один раз**, а трансформация выполняется полностью на GPU.
- **Облегчение теней**:
  - Отключение многоцветных `spotColor`/`ambientColor` на устройствах ниже Android 10 (API 29), где эти атрибуты эмулируются софтверно и нагружают процессор. Использование классической легковесной тени.
- **Оптимизация индикатора прогресса**:
  - Использование прямого лямбда-прогресса в `LinearProgressIndicator` без вызова промежуточных рекомпозиций.

### Шаг 3: Устранение GC-пауз и оптимизация Canvas в визуализаторе (`AudioVisualizerView.kt` и `AudioVisualizerController.kt`)
- Вынесение всех объектов `Brush` (вертикальный градиент, горизонтальная линия, радиальный bloom) из блока `onDraw` в `remember(colorStart, colorMiddle, colorEnd)`. Это снижает количество аллокаций памяти до 0 на кадр.
- В `AudioVisualizerController`: для старых систем (`isLowPowerDevice`) адаптивный шаг опроса `delay(33)` (~30 FPS), что экономит до 40% ресурсов CPU и оставляет весь бюджет времени на плавную 60 FPS анимацию интерфейса.

### Шаг 4: Оптимизация 3D-переворота обложек и списков
- Для старых систем: упрощенный, легковесный флип с аппаратным ускорением без избыточных перспективных искажений.
- Устранение лишних наложений прозрачности в фоновых слоях плеера.
