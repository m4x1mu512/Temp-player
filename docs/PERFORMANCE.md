# Производительность

Документ фиксирует, что уже сделано для плавности и быстродействия на Android 8+,
что требует проверки на устройстве и что осталось.

## Как измерить

```bash
# нужен телефон с USB-отладкой (adb devices)
./gradlew :benchmark:connectedDebugAndroidTest
```

Подробности и чтение отчёта — в [benchmark/README.md](../benchmark/README.md).
Замеры идут на `benchmark`-сборке: R8 включён, как в релизе, подпись отладочная.

## Что сделано

### Данные и диск

- Фильтрация, сортировка и группировка библиотеки — на `Dispatchers.Default`, не на UI.
- Поиск без `lowercase()` на каждый трек: `contains(ignoreCase = true)`.
- SQL больше не сортирует всю таблицу (`ORDER BY title COLLATE NOCASE`) — сортировка одна, в памяти.
- Списки id чанкуются по 900: `IN (:ids)` с 1000+ параметров падал на Android 8–11
  («too many SQL variables»), ломая сканирование и восстановление очереди.
- Сканирование: транзакция на вставку + удаление устаревших (одна инвалидация вместо N),
  теги читаются только для новых строк и строк без длительности/обложки.
- Длительность трека пишется в базу только при расхождении >1.5 с.
- Ни одной синхронной записи на диск в UI-потоке: `apply()` вместо `commit()`,
  `Dispatchers.IO` для состояния, все слайдеры (эквалайзер, скорость, тон, громкость,
  чувствительность, кроссфейд) пишут на диск один раз — после окончания жеста.
- Плейлисты больше не держат по живому запросу к Room: кэш на `WhileSubscribed`.

### Рендеринг

- Прогресс-бары читают анимацию в draw-фазе, без нового шейдера на кадр.
- Визуализатор: без FFT и публикаций, когда его никто не рисует (свёрнутый плеер,
  вкладка библиотеки, экран разрешений); переиспользуемые буферы и предвычисленное окно
  Ханна; данные читаются в draw-фазе, а не в композиции.
- Кривая АЧХ эквалайзера переиспользует `Path`, точки и `Stroke`.
- Обложки декодируются под размер отрисовки, коллажи карточек останавливаются на четырёх
  обложках вместо разбора URI всех треков группы.
- Состояние диалогов (эквалайзер, таймер сна, плейлисты) и избранного не перекомпоновывает
  целые экраны; колбэки секций стабильны (`remember`).
- `ColorScheme` темы кэшируется по (тема, акцент).
- Отчёт Compose-компилятора: 48 из 48 композаблов `skippable`.

### Запуск

- `PlaybackService` создаётся после первого кадра, а не на пути к нему.
- Второй ExoPlayer (нужен только для кроссфейда) создаётся через 3 с после начала
  воспроизведения; при выключенном кроссфейде — не создаётся вовсе.
- Синхронное восстановление очереди из `init` удалено (оно всегда падало: Room запрещает
  запросы на главном потоке).
- R8 + `shrinkResources` в release: один dex вместо тринадцати, APK 4,0 МБ против 25,6 МБ debug.
- Baseline-профили AndroidX (5902 правила) устанавливаются через `ProfileInstaller` на Android 8–11.

### Аудио

- DSP-цепочка обходится, когда эффект фактически не меняет сигнал (все эффекты выключены;
  эквалайзер в FLAT с единичным preamp).
- Базовый процессор не копирует буфер до проверки bypass.
- RMS для ReplayGain считается без переключения на главный поток 30–50 раз в секунду.

## Что проверить на устройстве

Эти изменения затрагивают поведение и не могут быть проверены статически:

| Область | Что смотреть | Коммит |
|---|---|---|
| Кроссфейд | переходы треков, особенно второй и третий подряд | `0ae6839` |
| Эквалайзер | изменение полос и пресетов слышно; FLAT звучит ровно | `ff4d719` |
| Сердечки | тап/повторный тап, вкладка «Избранное», после перезапуска | `b120e1d` |
| Запуск сервиса | мини-плеер появляется, воспроизведение из уведомления работает | `4a64914` |
| Визуализатор | все четыре режима рисуются и реагируют | `5415945` |

Откат любого пункта — `git revert <коммит>`; остальные изменения сохранятся.

## Что осталось

1. **Собственный baseline-профиль** — генерируется только на устройстве
   (`BaselineProfileGenerator` в модуле `:benchmark`), даёт −15…30 % к холодному старту.
2. Изменения внешнего вида, которые сознательно не трогались: 900-мс анимация цветовой
   схемы плеера, `scale`-переход при входе в папку, blur стекла мини-плеера.
